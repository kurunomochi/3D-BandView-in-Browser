# 让 Blender 作品在浏览器里转起来：Rust + Three.js 3D 预览上线

之前，我的博客作品集只能展示渲染图和视频。它们能记录最终效果，但观察角度是固定的：想看背面、靠近某个细节，访客只能等我再补一张图。所以这次我给作品集加了一个新功能——上传 Blender 工程后，可以直接在网页里旋转、缩放和平移模型，也能上下左右、前后移动视角。

我是 Rust async 初学者，这个博客也是我的实践项目。这次继续借助 AI 协作完成实现和测试，把 Rust 后端、Linux 进程管理与浏览器 3D 展示连成了一条完整流程。这篇文章记录目前真正做到了什么，以及还有哪些限制。

## 现在可以怎样看作品

在带有 3D 模型的作品详情里，点击「加载 3D 模型」后就能开始观察。模型按需加载，普通浏览作品图片时不会直接下载大模型文件。

- 鼠标左键拖动：围绕模型旋转。
- 鼠标右键拖动：平移视角；滚轮：拉近或拉远。
- 点击画面后，W/A/S/D 或方向键：前后左右移动；Q 下降，E 上升，R 重置。
- 页面上也有六方向移动按钮、速度调节和全屏按钮。
- 手机上可以单指旋转、双指缩放和平移。

这里的移动没有碰撞检测，可以穿过模型。它更适合自由查看作品，而不是带物理碰撞的游戏漫游。

## 浏览器并不直接读取 .blend

`.blend` 是 Blender 工程文件，里面可能包含网格、修改器、节点材质、外部贴图等。网页查看器读取的是服务器转换后生成的 GLB，而不是直接在浏览器里运行 Blender。

完整流程是：后台上传 .blend → Rust 保存非公开原文件 → Linux 启动隔离的 Blender 转换进程 → 导出并校验 GLB → 后台显示转换完成 → 保存作品 → 访客在详情页交互查看。

如果已经在本机导出了 GLB，也可以直接上传，省去服务器转换。GLB 必须把贴图和缓冲数据包含在文件内部，当前实现不接受依赖外部地址的模型，也没有配置 Draco、KTX2 等额外解码器。

## Rust 异步在这里做了什么

后端沿用 Axum 和 Tokio。上传接口先检查管理员登录状态，再检查格式和大小，把文件保存到任务目录。创建任务后，接口返回任务 ID，后台通过轮询查询 processing、ready 或 failed 状态，页面不用一直等着某一次请求返回转换结果。

转换任务使用 tokio::spawn 调度，再通过 tokio::process::Command 启动独立的 Python / Blender 进程。异步等待让后端能继续处理其他请求；真正的模型计算仍然消耗 CPU 和内存，并不会因为用了 async 就变快。

为了照顾这台约 2 GB 内存的服务器，我用 Semaphore 将同时上传或转换的模型任务限制为一个。已有任务运行时，新请求会得到「稍后再试」的提示；这里没有无限排队。转换等待超过 150 秒会停止，进程还设有单线程、内存和输出大小限制。

任务状态目前放在内存中，所以重启服务后无法继续查询旧任务；未完成的任务需要重新上传。已经保存到作品里的模型链接和磁盘文件则会保留。

## 为什么要把转换放进隔离环境

Blender 工程可能包含脚本或引用其他文件。转换时禁用了工程脚本自动执行，清空继承的服务环境变量，并用 bubblewrap 隔离网络和文件系统。转换进程只能使用运行环境和当前任务目录，不需要接触网站的管理员密码或其他作品数据。隔离条件不满足时会失败，不会退回到无隔离执行。

原始 .blend 与转换日志保存在非公开目录，网页使用的 GLB 放在公开上传目录。也就是说，访客可以获取展示用模型；它不是模型版权保护或防下载功能。上传前仍应确认工程来自可信来源，并且可以公开展示其中的资源。

## 前端如何实现

查看器使用 Three.js，GLTFLoader 负责加载 GLB，OrbitControls 负责旋转、平移和缩放。模型加载完成后，根据包围盒计算中心和初始观察距离，让不同尺寸的作品都能有一个可用的初始视角。

前后左右移动时，同时移动相机位置和控制器目标点；上下移动沿场景的竖直方向。这样既保留拖动旋转，也能走近某个细节。模型离开屏幕或页面进入后台时会暂停绘制，减少不必要的消耗。

Three.js 资源放在网站自己的目录里，并保留依赖许可证，不需要访客连接第三方 CDN。

## 怎样上传自己的作品

进入作品工作室，新建或编辑作品，在「3D 交互模型」区域选择 .blend 或 .glb。目前上传上限是 50 MiB，转换结果上限是 100 MiB。等待提示模型准备完成后，再点击「保存作品」。没有单独上传封面时会使用模型占位图，也可以用渲染图作为封面。

上传 .blend 前，先在 Blender 使用「文件 → 外部数据 → 打包资源」，把链接库转为本地数据，并确认场景里有可见网格。网页展示的是当前姿态的静态模型。程序化材质、毛发、体积、模拟和复杂节点可能需要先烘焙或转成网格，不能期待与 Cycles 最终渲染完全一致。

## 这次验证了哪些东西

上线前使用独立测试场景检查了转换和网页展示，测试了旋转、移动按钮、全屏和手机尺寸布局，也完成了后台 GLB 上传与作品保存。上线后又通过公网验证了 .blend 上传、隔离转换、GLB 下载及 HTTP Range，并确认原文件和日志不能通过网站访问。

转换测试中的工程带有一段用于验证的自动执行脚本，结果确认它没有被执行。已有文章和作品在部署前后保持一致；测试用上传文件已经清理，没有把测试作品发布到正式作品集。
